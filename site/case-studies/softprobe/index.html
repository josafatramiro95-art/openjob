OpenJob

We hire through our own open board

Softprobe · November 2026

Board

Softprobe is hiring a Software Engineer for AI Agent QA & Observability. The job is posted exactly one place first: OpenJob, our own open board. The post is a Markdown file in a public GitHub repository. It took one pull request to publish, and the moment it merged, every agent that reads OpenJob could find it.

This is the post: Software Engineer — AI Agent QA & Observability — it links to our Wellfound listing, and to hr@softprobe.ai. There is no application form on OpenJob itself. There never will be. Applying happens on the employer's own page, and for this role the employer is us.

Why we posted it as a file

A conventional board would have asked us to fill in a form, pick a pricing tier, and wait for candidates to come to the listing. OpenJob inverts that. The listing is a text file with structured fields — title, company, location, apply link, apply email — and the board is a Git repository. The file is the listing. Anyone can read it, link it, fork it, or check its history.

That matters because the people we want to hire already have agents. They do not browse job boards; they ask the agent they already use — Muse, ChatGPT/Codex, Cursor, Hermes, Instinct — to find them a job. So the question is not how to get a candidate to visit our board. It is how to get our role into the database their agent already reads. A public, agent-readable file does that. A form behind a login does not.

How an agent finds this role

There are three ways in, and they all work today:

  1. Paste a prompt. “Read https://openjob.softprobe.ai/llms.txt and follow it. Find me a job.” The agent reads the contract and searches the board.
  2. Call the MCP server. https://openjob.softprobe.ai/api/mcp — list_jobs, get_job, and the rest, no API key, no account.
  3. Download the dataset. The complete manifest at https://openjob.softprobe.ai/api/data/manifest.json lists every shard with SHA-256 checksums. The agent downloads all of them, verifies both checksums, and ranks locally.

That third path is the one we use ourselves, and it is worth describing exactly, because it is the reproducible part. The method is: download every shard; verify the gzip checksum and the raw checksum for each; filter to posts from the last 60 days; rank locally with your own code; then verify every apply link live before showing a match to anyone. Never invent a contact — the post's own apply method is the only one that exists. That is the whole method. There is no ranking service and no matching API, by design: OpenJob returns facts and source links, and the agent does its own matching.

What happens after a match

A match is a permalink and an apply method. The candidate follows the link to our Wellfound listing or emails hr@softprobe.ai. From there it is an ordinary hiring process: intro call, technical conversation, decision. OpenJob's part ends at the introduction — it is not an ATS, not an inbox, and not a messaging product, and we do not want it to become one.

What this proves, and what it doesn't

It proves the model works end to end for one real role: file in, agent-readable out, candidate in touch through the employer's own channel. It does not prove scale — one company page and one native job is the honest baseline, and this plan's target is 30 native posters. It also does not prove the role will be filled this way. If it is, we will say so with the real numbers. If it isn't, we will say that too.

The point of hiring through our own board is not to claim it is better. It is to eat the failure modes first: if a post is hard to write, if the validation rejects a reasonable file, if an agent cannot find a role that is plainly there, we hit it before any other employer does. That is the only honest way to ask other employers to post.

Try it with our role

Paste this into the agent you already use:

Read https://openjob.softprobe.ai/llms.txt and follow it. Find me a job in AI agent QA or observability.

If it brings you our role, the system works. If it doesn't, open an issue at https://github.com/softprobe/openjob/issues — that is also part of the point.
